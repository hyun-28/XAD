## 1. Task A — 데이터가 무엇인지 확정했다

### 1.1 우리가 가진 데이터가 공식본과 같은가

공식 zip을 새로 내려받아 로컬 사본과 파일별 SHA256을 대조했다.
**266개 파일 전부 일치, 불일치 0, 한쪽에만 있는 파일 0** (`data/raw/ucr/audit_a1.json`).
시리즈 `.txt`는 정확히 **250개** — 200개였다면 SIGKDD 공모전판이라 STOP 대상이었다.

부수적으로 알아낸 것: 공식 zip(184 MB)은 로컬 zip(92 MB)을 **안에 통째로 품고 있고** 거기에 압축 해제본을
덧붙인 구조였다. 크기가 2배라 처음엔 다른 판본을 의심했으나, 실제로는 같은 데이터의 이중 포장이었다.

### 1.2 이상 구간 인덱스 규약 (가장 조용한 버그)

파일명의 `begin`/`end`가 0-based인지 1-based인지, 끝점을 포함하는지는 **문서로 확정해야 하는 사항**이었다.
아카이브 자체 슬라이드(`UCR_AnomalyDataSets.pptx`)에서 근거를 찾았다:

- 슬라이드 4: `L = end – begin + 1` → 끝점 포함
- 슬라이드 5: "From 1 to X is training data", "Files are '-ascii' format" → MATLAB 1-based
- 슬라이드 52·53·90–99: 이상 주입 코드 `T(start_anomaly:end_anomaly)` → 1-based 포함 구간

실측으로도 교차 확인했다(1~2점짜리 이상 20개를 두 해석으로 플롯, `reports/figures/index_convention/`).
→ **`matlab_1based_inclusive` 확정, 연구자 승인 2026-09-22** (D-A2-3). 모든 코드는
`src/data/conventions.py`의 단일 상수를 거쳐 0-based 반열린구간으로 변환한다.

### 1.3 250개 전수 감사

형태·결측·길이·순서·이상 길이·상수 구간을 전부 검사해 **STOP 0건, WARN 0건**

도메인 분류는 Goswami et al.(ICLR 2023)의 **원본 매핑을 저장소에서 그대로 가져왔다**

## 2. Task A 후속 — 검토에서 드러난 두 문제

Task A 결과를 검토하는 과정에서 **브리프가 다루지 않았던 문제 두 개**가 나왔고, 둘 다 이후 모든 통계에 영향을 준다.

### 2.1 250개는 독립 표본이 아니다 → 분석 단위 변경

이름에서 `DISTORTED`/`NOISE` 접두사를 떼면 고유 이름은 **100개**다.
더 나아가 신호 내용으로 묶으면(학습 구간 앞 5,000점 z-정규화 후 피어슨 상관 ≥ 0.95) **89개 그룹**이 된다
(`reports/recording_groups.csv`, 비교 쌍 1,037개 전부 기록).

문제는 **18개 content_group이 서로 다른 이름을 가로지른다**는 것이었다 — 250개 중 146개 시리즈가 여기 해당한다.
`CIMIS44AirTemperature1~6`, `GP711MarkerLFM5z1~5`, `Tkeep*MARS` 5종, `insectEPG1~5`,
`PowerDemand1~4 + Italianpowerdemand`, `gait1~3`, `tiltAPB1~4` 등은 **같은 녹음에 서로 다른 이상을 주입한 것**이다.
정상 구간이 비트 단위로 같으므로 이름 기준으로는 독립성을 주장할 수 없다.

상관 분포는 완전 이봉형이었다(이름 간 772쌍 중 0.8–0.95 구간이 **0쌍**, ≥0.95가 452쌍이고 대부분 r = 1.000)
— 임계값 선택의 문제가 아니라 실제로 같은 녹음이라는 뜻이다.

→ **연구자 결정: 주 분석 단위 = `content_group`(89), `name_group`(100)은 민감도 분석** (D-F2-2).
`configs/stats.yaml`에 명시했고, 부트스트랩도 그룹 단위로 재표집한다.

### 2.2 −999 결측 표시값 — 브리프의 전제가 데이터와 달랐다

23개 시리즈에 정확히 −999인 지점이 있다(총 823개). 브리프의 전제는 "정상 구간에 이미 하드 마스킹이 들어 있어
기준선이 오염된다"였다. **실측 결과 그 전제가 성립하지 않았다:**

- 해당 23개 시리즈는 **±2047 스케일의 12-bit 신호**다. −999는 그 범위 안의 보통 값이다.
- 823개 점 중 국소 스파이크(w=51, k=10 기준)는 **0개**. 최대 비율 6.99는 슬라이드 46이 주입했다고 명시한
  185번 `resperation11`의 그 한 점이고, 나머지는 ≤ 4.53이다.
- 쌍둥이(DISTORTED/NOISE) 검사에서도 26개 중 25개가 `absent`.
- 브리프가 지정한 근사 탐지(학습 구간 MAD의 3배)는 tol이 180~1,600이 되어 신호 범위를 덮어버린다
  (68개 시리즈 620만 점이 걸림). **사용 불가.**

→ **연구자 결정: −999는 정상 측정값으로 취급, 주 분석에서 제외하지 않음** (D-F3-4).
`no_sentinel` 서브셋과 제외 인덱스 파일은 민감도 분석용으로 유지.

### 2.3 부수 작업

- 서브셋 정의 분리: `non_medical`(100 시리즈 / 22 그룹)과 `physical`(42 / 7)은 다른 개념임을 명시 (D-A5-4).
  **둘 다 그룹 수가 30 미만이라 가설검정 불가, 기술통계 전용**으로 표시된다.
- 데이터 라이선스 확정: 아카이브에 명시 라이선스 없음, 인용 2건 지정, 원본 재배포 금지 (D-A1-4).
- 레거시 로더 `src/data_ucr.py`의 하드코딩된 인덱스 계산을 규약 모듈 경유로 교체.
  **250개 전부에서 기존 결과와 동일**함을 테스트로 입증 → 기존 dry-run 결과가 무효화되지 않음 확인.

## 3. Task B — 탐지기 래퍼

### 3.1 왜 필요했나

Artifact Index는 "같은 모델에 원본을 넣은 점수 vs 섭동본을 넣은 점수"의 차이다.
그런데 TSB-AD의 `run_Unsupervise_AD()`는 **호출할 때마다 재학습한다.** 그대로 쓰면 점수 변화에
섭동 효과와 재학습 분산이 섞여 측정 자체가 성립하지 않는다.

### 3.2 소스를 끝까지 읽고 찾아낸 함정 (`docs/TSBAD_INTERNALS.md`, 줄 번호 전부 기록)

1. **조용한 실패**: `run_Unsupervise_AD`는 `except:`로 모든 예외를 삼키고 **에러 문자열을 반환한다**.
   루프에서 쓰면 쓰레기 값이 조용히 섞인다.
2. **`normalize` 불일치**: `fit()`은 윈도우 행렬을 z-정규화하는데 `decision_function()`은 하지 않는다.
   실측 최대 차이 0.0167. → 래퍼가 `normalize=False`를 강제하고, `True`를 넘기면 예외를 던진다.
3. **sklearn ≥ 1.6에서 파손**: `check_is_fitted`가 `AttributeError`를 낸다. `fit()`은 멀쩡해서
   **섭동 점수를 내기 시작할 때 비로소 터진다.** → `scikit-learn<1.6` 고정.
4. **`max_features=1`이 int다**: `run_IForest`의 기본값은 int 1 — sklearn에서 이는 "트리당 윈도우 열 1개"를
   뜻한다. 클래스 기본값 `1.`(float, 전체 열)과 **다른 모델**이다. 게이트에서 두 설정을 모두 돌렸다.

### 3.3 산출물

`fit_detector()` → `score()` 인터페이스, 반환값 7종 검증(문자열/길이/NaN/상수/dtype…),
호출 로그(`runs/<id>/calls.jsonl`), 그리고 **벤치마크 경로와 점수가 비트 단위로 일치함을 테스트로 입증**.
하이퍼파라미터 기본값은 임의로 고르지 않고 TSB-AD 벤치마크 드라이버가 실제로 넘기는 값을
소스 추적으로 확정했다(윈도우 100, 트리 200, `max_features` int 1 — D-B2-1).

환경도 `environment.yml`로 새로 만들어 검증했다(torch 2.3.0, sklearn 1.5.2, **테스트 142개 통과**).

## 4. Task C — 게이트 1: 미달 → 탐지기 교체 → 통과

### 4.1 사전 등록

결과를 보기 **전에** 판정 기준을 고정했다(`src/gate1.py`):

- **P1(주 기준)**: 이상 구간의 최대 점수 > 정상 테스트 구간 점수의 99 백분위수.
  버퍼는 0과 윈도우 길이 두 조건 모두 산출하되, **게이트 판정은 버퍼 = 윈도우**로 한다(D-C2-1).
  이유: TSB-AD는 윈도우 점수를 윈도우 중앙에 기록하므로, 버퍼 0이면 이상 구간의 점수가 정상 구간으로
  약 w/2만큼 새어 들어가 임계값을 부풀린다 — 이상을 자기 자신과 비교하게 된다.
- **P2(보조)**: 아카이브 자체 채점 규칙을 슬라이드에서 찾아냈다
  (`min(begin−L, begin−100) < P < max(end+L, end+100)`). 브리프에 적힌 `±100` 버전과 함께 둘 다 보고.

### 4.2 1차 — IForest: 미달

250 시리즈 × `fit_on` 2종 × `max_features` 2종 × seed 3개 = **3,000회 학습, 실패 0, 705초**.

| fit_on | max_features | P1 (seed 중앙값) |
|---|---|---|
| train_prefix | 1 (벤치마크 기본) — **주 조건** | **28.4%** |
| train_prefix | 1.0 | 38.8% |
| full | 1 | 30.0% |
| full | 1.0 | 39.2% |

**네 조건 전부 50% 미만.** 도메인별로는 Power Demand 0%, Air Temperature 3.8%, RESP 11.8%.

→ 사전 규칙에 따라 **탐지기 교체**. "IForest를 `max_features=1.0`으로 바꿔 쓰자"(39.2%)와
"탐지된 부분집합만으로 재설계"는 **채택하지 않았다** — 전자는 결과를 보고 기준을 바꾸는 것이고,
후자는 표본 구성이 IForest에 편향되기 때문이다 (D-C5-1).

후보 순서도 결과를 보기 전에 등록했다: MatrixProfile → Sub_PCA → KMeansAD (D-C5-2).

### 4.3 2차 — MatrixProfile: **통과**

구현 과정에서 STOP이 한 번 걸렸다. **TSB-AD의 `MatrixProfile`은 48줄짜리이고 메서드가 `fit` 하나뿐이다.**
self-join만 하고 `decision_function`이 아예 없어서, 사전 등록한 "학습 구간 참조 AB-join"이 불가능했다.
보고 후 연구자 승인을 받아 stumpy를 직접 호출하도록 구현하되, **self-join 설정에서 TSB-AD의 출력과
완전히 일치함(최대 차이 0.0)을 테스트로 입증**하고 그 위에 AB-join을 얹었다 (D-C5-3).

250 시리즈 × 2 조건, **실패 0, 5,012초**. 윈도우는 벤치마크대로 시리즈별 자동 추정(최소 6, 중앙값 125, 최대 276).

| 조건 | P1 (buffer=w) | P1 (buffer=0) | P2 archive |
|---|---|---|---|
| **train_prefix (AB-join) — 주 조건** | **79.2%** | 76.4% | 54.0% |
| full (self-join) | 82.8% | 80.0% | 58.8% |

→ **게이트 통과 (79.2% ≥ 50%).** 사전 등록 순서에 따라 2·3순위 후보는 실행하지 않았다.

도메인별(주 조건): EPG 96.0 / Air Temperature 92.3 / Gait 87.9 / ABP 85.7 / ECG 84.6 / NASA 81.8 /
Power Demand 36.4 / RESP 29.4 / Acceleration 28.6 (%).
IForest에서 0%였던 Power Demand와 3.8%였던 Air Temperature가 크게 올랐다.

### 4.4 판정 전에 고정해 둔 것

정렬 문제 하나를 발견했다. 윈도우 점수가 `시작 + w//2`에 기록되므로, **이상 길이가 w보다 짧으면
점수 최대점이 이상 구간보다 앞에 떨어질 수 있다** — P1이 읽는 구간 밖이다.
이걸 발견한 시점이 판정 직전이라, **기준을 유리한 쪽으로 고르는 일을 막기 위해 처리 규칙을 먼저 기록했다**
(D-C5-6, 기록 시각 13:02:58Z, 당시 게이트는 232/250 진행 중이었고 성공률은 계산조차 하지 않은 상태):

> P1과 진단치가 50% 기준에서 같은 쪽이면 그대로 판정. P1 < 50% ≤ 진단치이면 STOP 후 연구자 판단.

결과적으로 진단치는 83.2%로 P1(79.2%)과 같은 쪽이었으므로 **판정 그대로 확정**.

### 4.5 사전 예측 검증

AB-join에서 학습 구간 윈도우는 자기 자신과 매칭되므로 점수가 ≈ 0이어야 한다는 예측을 미리 등록했고,
**최대 3.3e-04로 성립**했다(1e-3 초과 시리즈 0개). 단 `train_end`를 걸치는 윈도우는 테스트 구간으로
넘어가므로 이 통계에서 분리해야 한다는 점을 구현 중에 발견해 컬럼을 나눴다.
→ 이후 AI 측정에서 학습 구간을 제외하는 근거가 확보됐다.

**결정성 확인:** 게이트를 두 번 돌려 `detection.csv`의 공통 35개 컬럼이 전부 일치함을 확인했다.

## 5. Task D — Šimić et al. 지표 이식 (BRIEF2)

### 5.1 D1 — DDS / PES / CMI 재구현

원 저장소를 커밋 고정(`edc6a870`)으로 가져와 `src/metrics/faithfulness_simic.py`에 재구현했다.
**무작위 곡선 1,000쌍(길이 2–60)에서 원본 함수와 최대 절대차가 정확히 0.0**
(요구 기준 `atol=1e-12`보다 강함). CMI는 부호 격자 400×58, PES는 무작위 부분집합 200개로 추가 검증.

원본 import에 MongoDB가 필요할 것으로 예상했으나 **실제로는 numpy/matplotlib/seaborn/math만 필요**해서
소스 추출 없이 원본 함수를 직접 불러 비교했다. MongoDB는 설치하지 않았다.

### 5.2 논문 대조에서 찾은 불일치

논문(Šimić, Veas & Sabol, *Sci Rep* 15:26607, 2025)을 확보해 Eq. 1–6과 코드를 대조했다:

- **Eq. 1–2 (DDS)**: 논문은 [0,1] 확률에 대한 가중 **합**, 코드는 0–100 스케일에 대한 가중 **평균**.
  정규화 후 같은 값이 된다 — 코드의 하드코딩 `100`은 **다른 공식이 아니라 단위 변환**이다(오차 8.9e-16로 확인).
- **Eq. 6 (CMI)**: 논문은 `DDS·PES ≥ 0`일 때 조화평균, 코드는 `pes*dds <= 0`일 때 0.
  **조건이 정반대다.** 차이가 나는 지점은 정확히 `DDS·PES = 0`인 집합이고, 수치는 양쪽 다 0이 되지만
  **논문 식을 그대로 구현하면 Python에서 `ZeroDivisionError`가 난다.** 브리프 지침대로 코드를 기준으로 구현했다.
- Eq. 3–5 (PES): 완전 일치.

### 5.3 D2 — AD 적응은 구현하지 않았다 (지시대로)

원 지표는 "예측 클래스 확률(0–100)이 섭동에 따라 얼마나 떨어지는가"를 잰다. 이상 점수에는 그대로 옮길 수 없다.
`faithfulness_ad.py`에 **시그니처와 docstring만** 두고 `NotImplementedError`를 던지게 했으며,
막히는 지점 4개(D7 추적 대상 / D8 정규화 / D9 방향 / D10 정상 구간 포함 여부)를 미결정으로 등록했다.

### 5.4 D3 — Wafer 모델 재현

`identify_zero_class.py`가 pymongo·captum을 module level에서 import하므로, 해당 절차만 줄 단위로 재현하되
원본 로더·네트워크·섭동기는 그대로 가져다 썼다.

- **정확도 재현: 25개 모델 전부 Δ = 0.000000** (브리프는 ResNet 1개만 요구했으나 전수 검증)
- **zero class가 아키텍처마다 다르다:**

| 아키텍처 | zero class 0 | zero class 1 |
|---|---|---|
| ResNet | **5 (전부)** | 0 |
| LSTM | 0 | **5 (전부)** |
| Inception | 3 | 2 |
| MLP | 4 | 1 |
| ViT | 3 | 2 |

LSTM과 ResNet이 정반대이고 나머지는 seed별로 갈린다. BRIEF2 D3가 "zero class 포함·제외 조건 모두에서
판정하라"고 한 이유가 이 표에 그대로 나타난다. (`reports/wafer_zero_class.csv`)
