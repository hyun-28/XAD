## 1. 원칙 → 코드 추적

## 2. §09 미해결 항목의 처리

### 2.1 가용성 — 닫힘

`broker/quorum.py`. 세 수준으로 나눴다.

- `FULL` — 전 컴포넌트 정상
- `DEGRADED` — 정족수 충족. 진행하되 저하를 명시
- `HALTED` — 진행 불가

**결정: 검증기 부재는 기본적으로 `HALTED`.** 검증기는 신뢰의 뿌리이므로
그것 없이 나온 출력은 근거 없는 출력이다. `VerifierDownPolicy.DEGRADE_WITH_WARNING`
으로 완화할 수 있으나 명시적 선택을 요구한다.

### 2.2 브로커 결정론 모드 — 닫힘

`broker/broker.py`. 세 모드.

| 모드 | 용도 | 재현 |
|---|---|---|
| `DYNAMIC` | 효율 최대 | 불가 (기록으로 대체) |
| `DETERMINISTIC` | 규제 배포 | 가능 |
| `REPLAY` | 과거 판단 재생 | 정확 |

**결정: 선택은 모드와 무관하게 항상 궤적에 남는다** (`SpanKind.SELECTION`).
`report.py --selections` 로 추출해 `Broker.load_replay()` 에 넣으면 동적
모드의 과거 판단도 정확히 재생된다. 재현성 구멍이 코어 하나로 국소화된다.

**추가 결정: 콜드 스타트 거부.** 기여도(value)는 순환적이다 — 돌려보기
전에는 모른다. `observations < min_observations` 면 `ColdStart` 를 던진다.
초기에는 고정 팀으로 운영하며 데이터를 모으라는 뜻이고, 이것이 로드맵의
1단계다.

### 2.3 코어의 위치 — 닫힘

**결정: 코어는 크기가 아니라 역할이다** (`Role.CORE`).

단일 프론티어 모델이 채우든 `ensemble.Deliberation` 이 채우든 인터페이스가
같다. 그래서 메모리 제약 환경에서 코어 박스만 앙상블로 갈아끼울 수 있고,
상위 코드는 바뀌지 않는다. 앙상블은 대안 아키텍처가 아니라 **구현 선택지**다.

### 2.4 컴포넌트 층위 평가 — 닫힘

`evaluation/component.py`. `ComponentEvalSet` 이 컴포넌트에 묶인 고정
테스트셋을 들고, `score_component()` 가 정확도와 **범위 정밀도**(범위 밖을
제대로 거절했는가)를 잰다. `decide_swap()` 이 세 비교를 순서대로 한다.

1. 절대 하한 → 미달이면 `ROLLBACK`
2. **T1 기준선 대비** → 못 이기면 `UNJUSTIFIED`
3. 현행 대비 → 개선 폭과 비용 상한

2번이 핵심이다. 이것이 없으면 "조합형의 우위는 검증 가능성"이라는 주장에
근거가 없다.

### 2.5 증류 경로 — 닫힘

`distill/pipeline.py`. 파라메트릭 진입 조건 3개를 `check_entry()` 가
**궤적에서 실측**한다 — 빈도와 스펙 안정성은 의견이 아니라 로그의 숫자다.
조건 미충족 시 `publish_contract()` 가 `EntryConditionsUnmet` 을 던진다.

`fallback` 없이는 발행되지 않는다. T1 은 버려지지 않고 비교 기준선이자
폴백으로 남는다.

### 2.6 도메인과 골드셋 — 부분적으로 닫힘

도메인은 **연구·학습 + 주식분석**으로 정해졌다. 두 도메인을 3기준으로
평가한 결과가 갈렸고, 그 갈림이 설계에 반영되었다.

| 기준 | 연구·학습 | 주식분석 |
|---|---|---|
| 결정론적 검증 가능성 | 중간 | **양극단** |
| 개입 라벨 축적 | 좋음 | 나쁨 — 개입 시점에 정답이 없다 |
| 반복 질의 빈도 | 중간 | 높음 |

**결정: 주식 도메인의 판단 계층에는 골드셋을 만들지 않는다.**

"종목이 올랐으니 분석이 맞았다"는 표본 1에 노이즈가 지배적이고, 백테스트
기반 평가는 룩어헤드 편향을 학습하는 과적합 기계다. 대신 검증 가능한 것에만
골드셋을 두고, 검증 불가능한 출력은 **라벨을 달아 분리**한다.

| 골드셋 | 위치 | 성격 |
|---|---|---|
| 출처 재현율 | `domains/research/goldset.py` | 필수·유용·금지 출처 3분류 |
| 시점 무결성 | `domains/finance/pointintime.py` | 결정론. 개수로 판정 |
| 지표 재계산 | `domains/finance/metrics.py` | 산술 대조. Judge 불필요 |
| 주장 분류 | `domains/finance/claims.py` | 검증 가능/불가 분리 |

**설계 결정: 권유형 출력(`ADVISORY`)은 기본 차단.** 이 도메인에는 그것을
평가할 골드셋이 없으므로, 검증된 숫자와 함께 내보내면 검증의 신뢰가
검증되지 않은 것으로 번진다. 시스템은 골드셋이 없는 것에 대해 골드셋이
있는 척하지 않는다.

**설계 결정: 룩어헤드는 검사가 아니라 구조로 막는다.** `AsOfView` 로
데이터 접근 경로를 하나로 만들면 검사를 빠뜨릴 수가 없다. `period_end` 와
`published_at` 을 분리해 갖는 것이 그 전제다.

**설계 결정: 기준일에 입력이 없으면 멈춘다.** 추정으로 메우면 그것이 곧
룩어헤드다. `examples/equity.py` 가 `service_level="halted"` 로 기록하고
무엇이 없는지 반환한다 — 예제 회귀 테스트가 잡은 결함이었다.

### 2.7 인용 수치 확인 — 열림

s3 의 "학습 시간 14배 · 비용 28배", AgentArcEval 11개 속성 명칭,
MoM 의 모델 개수·라운드 수는 여전히 원문 대조가 필요하다. 코드와 무관하나
발표 자료에는 영향이 있다.

## 3. 구축 중 새로 내린 결정

### 3.1 자식 사용량은 부모로 자동 합산

`trace/context.py`. 스팬 종료 시 부모의 `Usage` 에 병합한다.
시스템 층위 집계가 별도 계측 없이 나오고, 계측을 수동으로 두면 빠지고,
빠지면 평가할 수 없다.

### 3.2 범위 이탈은 예외가 아니라 값

`Component.__call__` 이 `Result(status=OUT_OF_ENVELOPE)` 를 반환한다.
예외로 던지면 상위에서 `try/except` 로 삼켜지기 쉽고, 값이면 궤적에
남고 집계된다.

### 3.3 격리 효과의 분모 바닥 처리

**테스트가 잡은 버그.** 상향 토큰이 0이면 격리가 **완전**했다는 뜻인데
`absorbed / emitted` 가 0을 반환해 지표가 반대로 읽혔다. `max(emitted, 1)`
로 바닥 처리했다. 완전 격리가 "격리 없음"으로 보이면 지표가 아니라
함정이다.

### 3.4 브로커 선택은 제어 결정으로 센다

`control_ratio` 계산에 `SpanKind.SELECTION` 을 포함한다. 동적 모드에서도
텔레메트리를 읽어 **코드가** 고르는 것이지 모델이 고르는 게 아니다.

### 3.5 검색기와 기억을 분리

`memory/store.py`. 규제 환경에서 둘은 완전히 다른 보존·삭제 규칙을 받는다.
`Memory.forget_subject()` 는 데이터 주체 단위 삭제를 지원하고, 문서
인덱스에는 그 요구가 번지지 않는다.

### 3.6 스킬 인덱스 절삭을 명시

`SkillLibrary.index()` 가 예산을 넘으면 `"... 외 N건 — 검색으로 좁히십시오"`
를 덧붙인다. 조용히 누락시키면 코어는 없는 스킬을 **없다고 판단한다.**

### 3.7 이차 투표를 단순 다수결 대신

`ensemble.quadratic_scores`. 한 심사자의 9크레딧 몰빵과 세 심사자의
1크레딧씩이 같은 무게(3.0)가 된다. 확신도를 반영하되 독점은 막는다.
단순 다수결이면 후자가 3표로 이긴다.

### 3.8 T1 을 동점으로도 못 이기면 거절

`decide_swap` 은 `candidate.accuracy <= baseline.accuracy` 를 `UNJUSTIFIED` 로
판정한다. 동점이면 기성품이 충분하다는 뜻이고, 그런데도 맞춤형을 두면
망각 위험과 관리 대상만 늘어난다. 교체는 **이겨야** 정당화된다.

### 3.9 홀드아웃은 학습 전에 자른다

`DistillationSet.split()` 이 중복 제거 후 앞에서 잘라 고정 평가셋을 만든다.
나중에 자르면 학습에 쓴 것으로 평가하게 된다. "평가셋이 코드보다 먼저
존재한다"를 증류 경로에서 구현한 형태.

### 3.10 검증 통과한 라벨만 학습에 쓴다

`DistillationSet.verified_only()`. 교사가 틀린 라벨을 학생이 배우면 그
오류는 이제 **가중치에** 들어가 되돌리기 어려워진다 — 사다리 6단의 비용이
정확히 그것이다. `verify` 를 주지 않으면 아무것도 신뢰되지 않는다(빈 학습셋).

### 3.11 앙상블은 비용과 VRAM 을 함께 보고

`Consensus.total_tokens` 와 `peak_vram_mb` 를 나란히 남긴다. 앙상블의
가치는 총 연산 절감이 **아니라** 최대 메모리 우회이므로, 둘을 같이 봐야
판단이 선다. 토큰만 보면 앙상블은 항상 손해로 보인다.

## 4. 알려진 한계

### 4.1 상관 증거를 탐지하지 못한다

`join_findings` 는 출처 ID 로 중복을 제거하므로 "같은 문서를 두 번 찾아온
경우"는 잡는다. 그러나 **서로 베낀 두 문서**가 같은 사실을 담으면 독립
출처 2건으로 계산된다. 해결하려면 출처 간 파생 관계를 모델링해야 하며,
현재 코드는 하지 않는다.

이는 1부에서 지적한 "거짓 합의" 문제의 절반만 해결한 것이다.

### 4.2 인용 검증이 주입식

`GroundingVerifier` 는 `entails` 콜러블을 받는다. 실제 NLI 모델 연결은
아직 없고, 예제에서는 문자열 포함으로 대체했다.

### 4.3 학습 자체는 외부에 있다

`distill/` 은 라벨 생성 · 중복 제거 · 홀드아웃 분할 · 진입 조건 검사 ·
계약 발행까지 한다. **학습 루프 자체는 포함하지 않는다** — 프레임워크가
학습 스택을 고르면 그 선택이 상각된다. `DistillationSet.write()` 가 JSONL
을 내보내고, 학습 결과를 `publish_contract()` 로 다시 받는 구조다.

### 4.4 저하 모드의 품질 표시가 호출자 몫

`QuorumDecision.degradations` 는 무엇이 저하됐는지 알려주지만, 그 사실을
최종 출력에 어떻게 드러낼지는 정하지 않는다. 저하 상태로 나온 답을
정상 답과 구분 없이 보여주면 정족수 설계의 의미가 절반 사라진다.
